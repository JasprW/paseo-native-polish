# Architecture

## Boundaries

`index.client.tsx` registers the settings screen, sidebar shortcut and Command Center action, then starts the web adapter. There is no server entry. Settings components use the public Paseo plugin UI and React Native primitives.

The public plugin API has no host-wide motion hook for existing sidebars or file trees. `client/web.ts` therefore contains a guarded DOM adapter and its minimal DOM types. Native platforms return a no-op. It does not import private React internals or patch the app bundle. All selectors target the Paseo 0.11.2 view structure.

## Capturing changes

Pointer-down captures layout before host gesture handlers commit. Click and keyboard activation cover other paths. A mutation observer and bounded frame polling catch asynchronous commits. Ambient updates use a per-frame set of dirty regions. Chat-local mutations update tools/messages without cloning workspace/project snapshots or measuring pane/tab layouts. Shell commits still discover all surfaces. Spinner leaf styles, elastic adapter style writes and ghost-only child-list mutations do not invalidate ambient layouts. Wheel bursts defer workspace snapshots until an idle rebase; virtualized membership changes during input do not look like workspace creation/removal.

Sidebars animate the actual width owner. A retained sidebar keeps its slot during exit; an unmounted Explorer gets an inert copy in that slot so adjacent panes resize. Pane, tab and reorder changes use bounded FLIP geometry. Disclosure animation watches direct membership changes; tree identity follows ancestor names and indentation rather than changing numeric row IDs.

Maximize/restore captures retain ownership for the full gesture, so the ambient membership observer cannot replay the same pane transition. Pane baselines exclude active parent/pane animation frames. Only outer sidebar width owners animate. Tab FLIP requires a real key-order change and uses tab-rail-relative positions; children do not get a second transition from sidebar/pane movement.

Menus preserve host-provided entrances where present. Exit copies have duplicate IDs and interactive media removed. They cannot receive focus or accessibility input. Newly appended message IDs fade once near the tail; initial history and virtualized remounts do not replay.

Workspace sidebar membership uses stable workspace test IDs, including mounted rows outside the viewport. Only visible rows and section headers get bounded snapshots. Creation fades in; removal uses an inert exit copy and scroll-relative FLIP positions for surviving neighbors. Initial list mounts, section toggles and active parent/sidebar animations rebase without row motion. Project trailing creation buttons are excluded from disclosure capture. Workspace row motion shares the sidebar preference.

Row order and section identity also detect pin/unpin and status migration when membership stays unchanged. Horizontal and vertical FLIP positions survive keyed row remounts. A new structural commit can interrupt existing row motion from its current visual position; animation-generated mutations do not restart it. Fully visible project groups get one entrance/exit owner, while clipped groups use visible rows and headers. A group containing a migrating workspace keeps that row under its own motion owner. Filter/grouping gestures rebase instead of looking like project deletion/creation.

## Motion lifecycle

`client/elastic-scroll.ts` handles vertical boundary input for the known chat/workspace/file/changes scroll roots using passive listeners. Supported Apple-platform browsers retain compositor overscroll with `contain`; Electron is excluded because its native bounce requires the main-process `scrollBounce` option. The fallback leaves scrollTop and native inertia under the host's control, skips nested code/detail scrollers and composes individual CSS translate with existing virtualizer transforms. Translated descendants are clipped inside the unchanged scroll content box to avoid extending scrollHeight. Feature/metric guards fail closed if the DOM or host styles differ. Pull follows input directly through a resisted distance curve; its extent depends on viewport height (36–100 px). Only release uses a critically damped spring, after a cadence-dependent 40–120 ms wheel-input gap or touch release. Momentum release bypasses this hold. Each wheel gesture retains a terminal release latch: sustained decay, spring return or cancellation closes it, and amplitude fluctuations cannot reopen it. A fling reaching an edge gets one displacement, then returns independently of its remaining tail. A 240 ms quiet gap or direction reversal starts another gesture; ignored tail events update the timestamp so they cannot repeatedly renew the pull. At a released boundary, line/page wheel impulses, spaced fresh pixel impulses or sustained renewed pressure above the tail low point can begin another pull without waiting for the old tail to expire. A continuous tail spike alone cannot reopen the latch: multiple meaningful non-decaying samples must confirm renewed pressure. Their input is retained and resumes from the visible offset. Event cadence is smoothed so sparse non-momentum input can remain held without changing the spring timing. DOM events do not expose the native momentum phase, so gesture segmentation remains approximate. New input resumes from the visible displacement. Active rebound suppresses ambient entrances; settling rebases the normal layout snapshots. Content changes, real scrolling and interaction cancel the feedback. Original boundary, clip, translate and custom-property values are restored without overwriting host changes.

Preferences use a small reactive store and client-local storage. Reduce Motion is observed live. Dragging, scrolling, preference changes and teardown cancel active animations. Cleanup removes temporary styles, inert copies, injected CSS, DOM markers, observers, timers and event listeners.

## Compatibility

The manifest limits the plugin to Paseo 0.11.x with a minimum of 0.11.2. The adapter was developed against 0.11.2. A compatible semver range does not establish that every host DOM revision has been reviewed. Inspect changed selectors and their retained/unmounted lifecycle before widening the range.
